# プロジェクト固有レビュー観点

汎用レビュー（可読性・エラー処理など）に**加えて**、以下を diff に対して機械的に確認する。各観点は「なぜ」を含む。判定できない項目は推測せず、実測するかユーザーに確認する。

## 1. 漏洩（最優先・ブロッカー）

public リポジトリで開発者個人の全作業ログを扱うため、1 件でもあれば即修正。

- [ ] diff・PR 本文・Issue に実ログのプロジェクトパス・プロンプト本文・PR URL が含まれていないか
- [ ] `~/.claude/settings.json` の permissions 実値が転記されていないか
- [ ] `tests/fixtures/` に追加されたデータは匿名化した**合成** JSONL か（実ログの切り貼りは匿名化しても不可）
- [ ] `reports/` や `.cache/` の出力がコミットに紛れていないか

## 2. Spec 整合

Spec が正本という規律が破られると spec:check が形骸化する。

- [ ] Spec の変更とコードが**同じ PR** に入っているか
- [ ] 新規テスト名が `SPEC-ID: 説明` 形式（ID 直後にコロン）か
- [ ] テストデータ中のダミー ID が予約領域 `SPEC-SAMPLE-*` に収まっているか
- [ ] 実装済みにした基準が `- [x]` に更新されているか
- [ ] `npm run spec:check` を実際に実行して乖離ゼロを確認したか（結果を見ずに「通るはず」としない）

## 3. ストリーム規律（メモリ・性能）

最大 69MB / 1 行 1.3MB のファイルが前提。全読み込みは規模が増えた瞬間に事故になる。

- [ ] JSONL 全体を `readFile` で読む変更が入っていないか（byte offset 走査を維持）
- [ ] インデックスに全文を持たせていないか（プレビューは 200 字まで）
- [ ] 全文検索に転置インデックスを持ち込んでいないか（ストリーム grep が設計判断）

## 4. 増分更新の整合性

「間違ったインデックスを高速に作る」ことが最悪ケース。

- [ ] 縮小・mtime 逆行・schemaVersion 不一致で全再構築へ倒れるか
- [ ] 改行で終わらない末尾行を `lastOffset` に含めていないか（含めると次回二重計上）
- [ ] 壊れた JSON 行がスキップ＋ `skippedLineCount` 計上になっているか（例外で全体を落とさない）
- [ ] 増分更新の結果が全再構築と一致するテストが維持されているか

## 5. コスト計算の暗黙劣化

「黙って過小計上」がこの領域の最悪ケース。0 円やエラーより悪い。

- [ ] 価格表に無いモデルが `unknownModel` 警告になるか（サイレント 0 円は不可）
- [ ] モデル ID の正規化が新しい修飾に耐えるか — 日付サフィックス（`-20251001`）は除去済みだが、`[1m]` のような**将来の修飾付き ID** が来たら未知モデル警告に落ちることを確認（警告に出れば設計どおり。黙って 0 円なら NG）
- [ ] fast mode / 導入価格の適用条件を変えていないか（fast は通常単価の 2 倍。取り違えは警告なしの 2 倍 undercount）
- [ ] UI・出力に「推定」の明示と単価の出典が残っているか
- [ ] 単価のハードコードが `server/pricing.json` の外に増えていないか

## 6. 中間層の境界（Codex 対応の布石）

viewer・API・集計が Claude 固有の JSONL 構造に依存すると、Codex CLI ログ対応時に全面改修になる。

- [ ] viewer / API / 集計側が正規化 DTO（`IndexRecord` / `SessionSummary` 等）だけを参照しているか（生の JSONL フィールド名が normalize の外に漏れていないか）
- [ ] DTO にソース固有フィールドを安易に生やしていないか（必要なら意味で抽象化して命名する）

## 7. サーバ境界

- [ ] bind 先が `127.0.0.1` のままか（`0.0.0.0` への変更は設計判断の変更。要相談）
- [ ] 認証を追加しない前提が崩れる変更（外部公開・トンネル）が入っていないか
- [ ] パスの組み立てで `~/.claude/` の外へ出られないか（表示時 seek の filePath がリクエスト起点なら特に）

## 8. UI・チャート（該当時のみ）

- [ ] チャートを書く前に `dataviz` skill を読み込んだか
- [ ] コスト表示にキャッシュ内訳があるか（実測でコストの約 94% がキャッシュ由来。input/output だけの表示は実態を取り違える）
