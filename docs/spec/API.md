# SPEC-API — HTTP API（基本仕様書）

担当 Issue: #5

## ゴール

インデックスを HTTP で提供する。`127.0.0.1` のみに bind し、認証は設けない（ローカルの個人ログを扱うため外部公開しない）。

画面（Overview / プロジェクト / セッション分析 / Tools & Agents / 設定・定義）が必要とするデータを、Claude 固有の JSONL 構造を隠した正規化済みの形で返す。

## できること

1. **全体俯瞰（Overview）** — 期間を指定して、総トークン・推定コスト・モデル別内訳・日次推移・プロジェクト一覧をまとめて取得できる
2. **プロジェクトのドリルダウン** — プロジェクトを指定して、日次のモデル別トークン推移・推定コスト・セッション一覧を取得できる
3. **セッションの詳細** — セッションを指定して、要約（モデル・トークン・推定コスト・ツール利用・破損スキップ行数）とメッセージ一覧のメタ情報を取得できる
4. **メッセージ本文の取得** — セッションのメッセージ本文を必要な範囲だけ取得できる（ファイル全体を読み込まず、該当行だけを seek して読む）
5. **全文検索** — キーワードを指定して全セッションを横断検索し、ヒットしたセッションと該当箇所を取得できる
6. **統計** — トークン（モデル別・日別）、ツール別ランキング、エージェント・スキル別の起動実績を取得できる
7. **設定・定義の取得** — `~/.claude/` 配下のエージェント・スキル・プラグイン定義と settings（permissions 実値を含む）を取得できる
8. **価格表の取得** — コスト計算に使っている単価表（`server/pricing.json`）を取得できる。コストが常に「推定」であることをレスポンスで明示する

## 挙動の約束

- サーバは `127.0.0.1` のみに listen する。ポートは既定 4517、環境変数 `PORT` で変更できる
- 起動時に `~/.claude/projects` を走査してインデックスを構築し、2 回目以降はキャッシュを再利用する（増分更新は SPEC-CORE の規約に従う）
- 壊れた JSONL 行があってもエラーにせず、スキップ件数を集計に含めて返す
- 未知モデルはコスト 0 円で黙らせず、レスポンスに未知モデル一覧を含めて画面が警告を出せるようにする
- 存在しないプロジェクト・セッションを指定したら 404 と JSON のエラーメッセージを返す（サーバは落ちない）

## 対象外（この Spec では扱わないこと）

- ライブ更新（ファイル監視・SSE）は SPEC-LIVE で扱う
- 画面そのもの（HTML / チャート）は SPEC-DASH・SPEC-CHAT で扱う

## オーナー確認方法

サーバを起動し、curl で各エンドポイントを叩いて実レスポンスを確認する:

```bash
npm run serve                                      # 127.0.0.1:4517 で起動
curl -s localhost:4517/api/overview | jq .totals   # 総トークン・推定コストが report と一致する
curl -s localhost:4517/api/projects | jq length    # プロジェクト数が ~/.claude/projects の実数と一致する
curl -s "localhost:4517/api/search?q=<語>" | jq    # 検索ヒットが実ログの内容と一致する
```

`npm run report` の数値（総コスト・レコード数）と API のレスポンスが一致することを確認の軸にする。

エンドポイント表・受け入れ基準は [docs/design/API.md](../design/API.md)。
